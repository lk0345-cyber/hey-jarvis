# 사내 파일 검색 AI (Jarvis File Finder) 기술 기획서

> 대상: 내부 개발자 / 작성일: 2026-10-07
> 목표: 맥미니(사내 서버)에 쌓인 파일을 자연어로 찾아서 바로 전달하는 사내 AI

---

## 0. 한 줄 요약

**"검색 엔진은 정확하게, 판단은 LLM이 자유롭게."**
파일을 미리 색인(파일명·경로·본문·의미 벡터·연도 등 메타데이터)해 두고, LLM 에이전트(기존 hey-jarvis / OpenClaw)가 **검색 도구(tool)** 를 상황에 맞게 골라 여러 번 호출해서 후보를 좁힌 뒤, 파일을 링크나 메신저 첨부로 전달한다.

LLM이 파일 시스템을 직접 뒤지게 하는 게 아니라 **잘 만든 검색 API를 LLM에게 쥐여 주는 구조**가 핵심이다. 정확도·속도·권한 통제가 모두 여기서 결정된다.

## 1. 요구사항 정리

### 1.1 사용 시나리오

| # | 사용자 요청 | 시스템이 해야 할 일 |
|---|---|---|
| A | "22년에 운영했던 마케팅 미디어 믹스 찾아줘" | 연도=2022 해석 + "미디어믹스/media mix/매체 믹스/매체계획" 동의어 확장 → 파일명·경로·본문 검색 → 후보 제시 → 전달 |
| B | "'미디어믹스'라는 단어가 들어간 파일 다 꺼내줘" | 본문 전문검색(키워드 정확 일치) 위주 |
| C | "작년 알보칠 제안서 최종본" | 클라이언트명 + 문서유형 + "최종/final" 버전 판별 |
| D | "유튜브 예산 비중이 높았던 캠페인 자료" | 의미(벡터) 검색 + 본문 스니펫 확인 |
| E | "22년 미디어믹스에서 유튜브 예산 얼마였어?" (확장) | 파일 찾은 뒤 내용 읽고 답변(RAG) |

### 1.2 "자유도"의 정의

자유도를 막연히 두면 품질이 들쭉날쭉해진다. 다음 3가지로 구체화한다.

1. **검색 전략의 자유도** – LLM이 질문을 보고 파일명 검색 / 본문 키워드 검색 / 의미 검색 / 폴더 탐색 중 무엇을, 어떤 순서로 쓸지 스스로 결정 (에이전트 루프, 최대 N회).
2. **질의 해석의 자유도** – "22년", "작년", "FY22", "2022 하반기" 같은 표현, 한/영 혼용, 띄어쓰기 차이, 동의어를 자동으로 펼침.
3. **응답 방식의 자유도** – 확신도가 높으면 바로 파일 전달, 애매하면 후보 3~5개를 근거와 함께 보여주고 선택받기, 사용자가 원하면 목록/요약/내용 답변.

반대로 **자유도를 주면 안 되는 영역**: 권한(누가 어떤 파일을 볼 수 있나), 파일 전달 방식, 로그. 이건 코드로 강제한다.

## 2. 전체 아키텍처

```
┌────────────────────────── 맥미니 (사내망) ──────────────────────────┐
│                                                                     │
│  [공유 스토리지]  /Volumes/Share (외장 SSD 또는 NAS SMB 마운트)       │
│        │  ① 변경 감지 (FSEvents / watchdog) + 야간 전체 스캔           │
│        ▼                                                            │
│  [Indexer 워커 - Python]                                             │
│     ② 텍스트 추출 (hwp/hwpx/pptx/xlsx/docx/pdf/OCR)                  │
│     ③ 메타데이터 추출 (연도·클라이언트·문서유형·버전·해시)           │
│     ④ 청킹 + 임베딩 (bge-m3, 로컬)                                   │
│        ▼                                                            │
│  [PostgreSQL 16]  files / chunks / tags / acl / synonyms / logs      │
│     + pgvector (의미검색) + pg_bigm (한글 2-gram 전문검색)            │
│        ▲                                                            │
│  [Search API + MCP 서버 - Python/FastAPI]                            │
│     ⑤ 하이브리드 검색 + 리랭킹 + 권한 필터                            │
│     ⑥ 파일 전달 (만료 링크 / 메신저 첨부)                              │
│        ▲                                                            │
│  [hey-jarvis (OpenClaw 게이트웨이)]  ← LLM 에이전트, tool 호출         │
│        ▲                                                            │
└────────┼────────────────────────────────────────────────────────────┘
         │
   Telegram / Slack / 사내 웹 UI  ← 직원
```

### 2.1 현재 레포(hey-jarvis)와의 관계

- 현재: OpenClaw 게이트웨이를 **Railway(클라우드)** 에 띄우고 Telegram으로 대화.
- 파일은 **맥미니(사내)** 에 있으므로 둘을 연결해야 한다. 선택지:
  - **(권장) 게이트웨이를 맥미니로 이전** – 파일·색인·에이전트가 모두 사내에 있음. 외부로 나가는 건 LLM API 호출(질문 + 짧은 스니펫)뿐. 구성 단순, 보안 유리.
  - (대안) Railway 유지 + Tailscale로 맥미니 Search API에 접근 – OpenClaw가 `tailnet` bind를 지원하므로 가능하지만, 장애 지점이 하나 늘어난다.
- 연결 방식: Search API를 **MCP 서버**로 노출하고 OpenClaw에 tool로 등록 (설치된 OpenClaw 버전의 MCP/플러그인 연동 방식은 개발 착수 시 확인). MCP로 만들어 두면 나중에 Claude Desktop, 다른 에이전트에서도 그대로 재사용 가능.

## 3. 컴포넌트별 상세 설계

### 3.1 스토리지 & 하드웨어

| 항목 | 권장 |
|---|---|
| 맥미니 | M4 Pro / 메모리 48GB 이상 (임베딩·리랭커·로컬 LLM 동시 구동 여유). 최소 M4 / 24GB |
| 저장소 | 썬더볼트 외장 SSD 또는 기존 NAS(Synology 등)를 SMB로 마운트 |
| 운영 설정 | 잠자기 해제, 정전 후 자동 부팅, UPS, 고정 IP, 모든 서비스 `launchd`로 자동 재시작 |
| 백업 | 원본 파일: NAS 스냅샷 or Time Machine + 외부 백업 / DB: `pg_dump` 일 1회 (색인은 재생성 가능하지만 수작업 태그·동의어는 백업 필수) |

> 원본 파일은 **읽기 전용으로 마운트**해서 인덱서가 실수로 수정·삭제하지 못하게 한다.

### 3.2 텍스트 추출 (가장 공수 많이 드는 부분)

| 형식 | 도구 | 비고 |
|---|---|---|
| `.hwp` (한글 5.0) | `pyhwp`(hwp5txt) → 실패 시 LibreOffice + H2Orestart 확장으로 변환 | 한국 회사 자료의 핵심. 표 안 텍스트 누락 여부 꼭 검증 |
| `.hwpx` | zip 해제 후 `Contents/section*.xml` 파싱 | 비교적 쉬움 |
| `.pptx` | `python-pptx` (슬라이드 텍스트 + 표 + 노트) | 마케팅 자료 대부분 |
| `.xlsx` / `.xls` | `openpyxl` / `xlrd` – 시트명 + 헤더 + 셀 값 | 미디어믹스는 엑셀이 많음 → 시트명·헤더 행이 매우 중요한 신호 |
| `.docx` | `python-docx` | |
| `.pdf` | `PyMuPDF` | 텍스트 레이어 없으면 OCR |
| 이미지/스캔 PDF | macOS Vision 프레임워크(`ocrmac`) – 한글 OCR 품질 양호, 무료, 로컬 | 대안: Tesseract(kor) |
| `.key`, `.pages` | 맥에서 PDF로 변환 후 추출 (또는 Phase 3로 미룸) | |
| 영상/디자인 원본 (psd, ai, mp4) | 본문 추출 안 함, **파일명·경로·메타데이터만** 색인 | |

- 추출 실패 파일은 `extract_status = failed`로 남기고 **파일명/경로 검색은 계속 가능**하게 한다 (본문이 없어도 찾을 수는 있어야 함).
- 파일당 추출 시간 제한(예: 60초), 대용량(>200MB) 파일은 메타데이터만.

### 3.3 메타데이터 추출 – "22년"을 정확히 맞히는 핵심

"22년 미디어믹스"의 성패는 **연도 판별**에 달려 있다. 파일 생성일/수정일은 복사·이동하면 바뀌므로 신뢰도가 낮다. 여러 신호를 모아 **신뢰도 가중치**로 결정한다.

| 신호 | 예시 | 신뢰도 |
|---|---|---|
| 폴더 경로 | `/마케팅/2022/`, `/22년 캠페인/` | 높음 |
| 파일명 | `2022_미디어믹스_v3.xlsx`, `22H2_MMP.pptx`, `FY22` | 높음 |
| 본문 날짜 | 표지의 "2022. 03", 엑셀 기간 컬럼 "2022-01~06" | 중간 |
| 파일 시스템 날짜 | 생성/수정일 | 낮음 |

추출 결과를 `years INT[]`(복수 가능: 22~23 연간계획 등)로 저장하고 `year_source`를 같이 기록한다.

그 외 추출할 메타데이터:

- **클라이언트/브랜드**: 사내 클라이언트 사전(yaml)과 경로·파일명 매칭
- **문서 유형**: 제안서 / 미디어믹스 / 결과보고서 / 견적서 / 계약서 / 회의록 … (규칙 + 부족하면 LLM 분류 1회)
- **버전**: `v1, v2, 최종, 최종_수정, final, final_final` 패턴 → 같은 그룹 내 "대표본" 판별
- **중복**: 내용 해시(SHA-256)로 동일 파일 묶기 → 검색 결과에서 1개만 노출, "다른 위치 3곳" 표시
- **문서 요약**: LLM으로 3줄 요약 1회 생성해 저장 (후보 제시 시 근거로 사용, 비용 아끼려면 Phase 2)

### 3.4 동의어 / 용어 사전 (실무에서 체감 정확도를 가장 크게 올리는 부분)

LLM이 동의어를 알아서 펼쳐 주긴 하지만, **회사 고유 용어는 모른다.** 업무 담당자가 관리하는 사전을 둔다.

```yaml
# synonyms.yaml (운영팀이 직접 수정)
미디어믹스:
  - 미디어 믹스
  - media mix
  - mediamix
  - 매체 믹스
  - 매체믹스
  - 매체계획
  - 매체 플랜
  - media plan
  - MMP
제안서: [제안, proposal, RFP 응답, 피칭, pitch]
결과보고서: [결과 보고, 리포트, report, 성과보고, wrap-up]
```

- 검색 시: 사전 확장(결정적) + LLM 확장(유연) **둘 다** 적용.
- 사용 로그에서 "검색 0건 → 사용자가 다른 말로 재검색해서 찾은 경우"를 모아 사전 후보로 제안 (Phase 3).

### 3.5 색인 (DB 설계)

**권장: PostgreSQL 16 + pgvector + pg_bigm (Docker로 맥미니에 구동)**

- 이유: 메타데이터 필터(연도, 확장자, 폴더, 권한)와 전문검색, 벡터검색을 **한 쿼리에서** 처리 가능. 운영 대상이 DB 하나.
- 한글 전문검색: 기본 `tsvector`는 한글 형태소 분석이 안 되고, `pg_trgm`(3-gram)은 "믹스", "예산" 같은 2글자 단어에 약하다 → **2-gram인 `pg_bigm`** 사용.
- 대안: 문서가 수십만 건 이상으로 커지면 **OpenSearch + nori(한글 형태소 분석기) + k-NN** 으로 이전 검토.

핵심 테이블:

```sql
files (
  id, path, filename, ext, size, sha256,
  created_at, modified_at, indexed_at,
  years int[], year_source text,
  client text, doc_type text, version_label text, is_representative bool,
  summary text, extract_status text,
  acl_groups text[]                  -- 권한 그룹
)
chunks (
  id, file_id, seq, location text,   -- "슬라이드 7", "시트: 2022 상반기", "p.3"
  content text,
  embedding vector(1024)             -- bge-m3
)
synonyms (term, variants text[])
search_logs (user_id, query, expanded_query, results jsonb, chosen_file_id, created_at)
share_logs  (user_id, file_id, channel, link_expires_at, created_at)
```

인덱스: `filename`·`path`·`chunks.content`에 `pg_bigm` GIN, `embedding`에 HNSW, `years`·`acl_groups`에 GIN.

### 3.6 임베딩 / 리랭킹 모델 (로컬 구동)

| 용도 | 모델 | 이유 |
|---|---|---|
| 임베딩 | **BAAI/bge-m3** | 다국어(한·영 교차검색: "미디어믹스" ↔ "media mix"), 긴 입력(8k 토큰), 로컬 구동 가능 |
| 리랭커 | **BAAI/bge-reranker-v2-m3** | 상위 50개 후보를 질문과 다시 비교해 정밀 정렬 |

- 맥미니에서 `sentence-transformers`(MPS 가속) 또는 MLX로 구동 → **파일 본문이 외부로 나가지 않음.**
- 초기 전체 색인은 파일 양에 따라 수 시간~수일 걸릴 수 있으므로 야간 배치 + 진행률 모니터링. 이후엔 변경분만.
- 청킹: 문서 구조 단위 우선 (슬라이드 1장, 엑셀 시트 1개, 문단 묶음 ~500토큰). 각 청크 앞에 `[파일명 | 경로 | 시트명]`을 붙여 임베딩하면 맥락 정확도가 올라감.

### 3.7 검색 로직 (하이브리드 + 가중치)

```
질문 ──► 질의 해석 (LLM)
         {keywords:["미디어믹스"], years:[2022], doc_type:"미디어믹스", client:null}
     ──► 동의어 확장 (사전 + LLM)
     ──► 권한 필터 (사용자 그룹) ← 반드시 DB 쿼리 단계에서 적용
     ──► 3갈래 병렬 검색
          ① 파일명·경로 매칭 (bigram)
          ② 본문 키워드 매칭 (bigram)
          ③ 의미 검색 (벡터)
     ──► RRF(Reciprocal Rank Fusion)로 합산
     ──► 가산점: 연도 일치(+), 문서유형 일치(+), 대표본/최종본(+), 중복 제거
     ──► 리랭커로 상위 50 → 상위 5
     ──► 결과 + "왜 찾았는지" 근거
```

**결과에 근거를 반드시 포함**한다 (신뢰의 핵심):

> 1. `2022_상반기_미디어믹스_최종.xlsx` — 경로 `/마케팅/2022/` · 파일명 '미디어믹스' 일치 · 시트 "매체별 예산" (2022-03-14 수정)
> 2. `22H2_MMP_v2.pptx` — 파일명 'MMP'(=미디어믹스) · 본문 "하반기 매체 믹스 전략" 슬라이드 4

### 3.8 LLM에게 줄 도구(Tool / MCP) 설계

도구는 **작고 조합 가능하게** 만든다. 그래야 LLM이 자유롭게 전략을 짠다.

| Tool | 입력 | 출력 | 용도 |
|---|---|---|---|
| `search_files` | `query`, `keywords[]`, `years[]`, `doc_type`, `client`, `ext[]`, `folder`, `mode`(hybrid/filename/content/semantic), `limit` | 후보 목록 + 점수 + 근거 + 스니펫 | 메인 검색 |
| `grep_content` | `phrase`, 필터들 | 해당 문구가 정확히 들어간 파일 + 위치 | 시나리오 B ("이 단어 들어간 파일") |
| `browse_folder` | `path` | 하위 폴더/파일 목록 | 검색이 안 될 때 폴더 구조로 탐색 |
| `get_file_detail` | `file_id` | 메타데이터, 요약, 주요 청크, 같은 그룹의 다른 버전 | 후보 확인 |
| `read_file_content` | `file_id`, `location?` | 본문 일부 | 시나리오 E (내용 답변) |
| `share_file` | `file_id`, `channel`, `expires_in` | 전송 결과 / 링크 | 최종 전달 |

- 모든 tool은 서버에서 **호출한 사용자의 권한으로** 실행 (LLM이 user_id를 바꿀 수 없게, 세션에서 주입).
- 에이전트 시스템 프롬프트 핵심 지침:
  - 연도·동의어를 먼저 해석하고 `search_files`부터 호출
  - 결과가 0건이면 조건을 완화(연도 제거 → 동의어 확장 → 의미검색 → 폴더 탐색) 하며 최대 4회 재시도
  - 1위 점수가 압도적이고 근거가 명확하면 바로 전달, 아니면 후보 3~5개를 근거와 함께 제시
  - 파일 내용을 지어내지 말 것. 확인 못 했으면 "확인 못 함"이라고 말할 것

### 3.9 파일 전달

| 방식 | 장점 | 단점 | 권장 |
|---|---|---|---|
| **만료 다운로드 링크** (Search API가 서명된 URL 발급, 예: 24시간) | 대용량 OK, 다운로드 로그 남음, 채널 무관 | 사내망/VPN(Tailscale)에서만 열리게 해야 함 | ✅ 기본 |
| **메신저 첨부** (Telegram `sendDocument`) | 가장 편함 | Bot API 50MB 제한, 파일이 메신저 서버로 나감 | ✅ 작은 파일 + 보안등급 낮은 파일 |
| **SMB 경로 안내** (`smb://macmini/Share/마케팅/2022/...`) | 복사 없음, 원본 위치를 알려줌 | 사내망에서만 | ✅ 링크와 함께 표기 |

- 보안 등급(예: 계약서·인사 폴더)은 **링크만 허용, 첨부 금지** 같은 정책을 코드로 강제.

### 3.10 권한 · 보안 · 개인정보

1. **권한 인지 검색(permission-aware retrieval)**: 폴더별 접근 그룹을 매핑(`acl_groups`)하고, 검색 쿼리 단계에서 필터. LLM 프롬프트로 막는 건 보안이 아님.
2. **사용자 식별**: Telegram/Slack ID ↔ 직원 ↔ 그룹 매핑 테이블. 미등록 사용자는 거부 (현재 `allowFrom` 설정 확장).
3. **외부 LLM으로 나가는 데이터 최소화**: 현재 모델(Fireworks GLM-5 / GPT-4o)은 외부 API. 질문 + 파일명 + 짧은 스니펫만 전송, 본문 전체는 전송하지 않음. 민감 폴더는 스니펫도 제외.
   - 더 엄격히 하려면 질의 해석·답변을 **로컬 LLM**(맥미니에서 MLX/Ollama로 Qwen3, EXAONE 등)으로 처리하는 옵션을 Phase 3에서 검토.
4. **감사 로그**: 누가, 언제, 무엇을 검색했고 어떤 파일을 받았는지 전부 기록.
5. **원본 보호**: 읽기 전용 마운트, Search API는 사내망/Tailscale에만 바인딩.

## 4. 예시 흐름: "22년에 운영했던 마케팅 미디어 믹스 찾아서 전달해줘"

```
1) LLM 질의 해석
   years=[2022], keywords=["미디어믹스"], doc_type="미디어믹스", dept_hint="마케팅"
2) 동의어 확장
   미디어믹스 → [미디어 믹스, media mix, 매체믹스, 매체계획, media plan, MMP]
3) search_files(mode=hybrid, years=[2022], ...)
   → 7건 (중복 제거 후 4건)
4) 1위: 2022_연간_미디어믹스_최종.xlsx (score 0.91)
   2위: 22H2_MMP_v2.pptx            (score 0.74)
   → 1위가 압도적이지 않음 + 상·하반기 자료가 나뉨 → 후보 제시
5) 응답:
   "2022년 미디어믹스 자료 2건을 찾았습니다.
    1. 2022_연간_미디어믹스_최종.xlsx — /마케팅/2022/ · 시트 '매체별 예산'
    2. 22H2_MMP_v2.pptx — 하반기 매체 믹스 전략 (슬라이드 4)
    둘 다 보낼까요?"
6) 사용자 "둘 다" → share_file ×2 → 링크(24h) + SMB 경로 전달, 로그 기록
```

시나리오 B("미디어믹스라는 텍스트 있는 파일 다")는 LLM이 `grep_content("미디어믹스")`를 선택 → 파일 + 위치(시트/슬라이드/페이지) 목록으로 응답.

## 5. 단계별 로드맵

| 단계 | 기간(예상) | 범위 | 완료 기준 |
|---|---|---|---|
| **Phase 0. 사전 조사** | 1주 | 전체 파일 수·용량·확장자 분포 조사, 폴더 구조/파일명 관행 파악, 권한 매트릭스, 동의어 사전 초안, **평가용 질문 50개 + 정답 파일** 수집 | 조사 리포트 + 평가셋 |
| **Phase 1. MVP (파일명·경로 검색)** | 2~3주 | 스캐너, 메타데이터(연도/버전/중복), PostgreSQL, `search_files`(filename 모드)·`browse_folder`·`share_file`, OpenClaw 연동, Telegram 전달 | 평가셋 Recall@5 측정, 파일명이 정돈된 자료는 바로 찾힘 |
| **Phase 2. 본문 + 의미 검색** | 3~4주 | 텍스트 추출(HWP·OCR 포함), 청킹, bge-m3 임베딩, 하이브리드+리랭커, `grep_content`·`get_file_detail` | Recall@5 ≥ 85% 목표 |
| **Phase 3. 운영 고도화** | 지속 | 권한 그룹 세분화, 웹 UI(검색창 + 미리보기), 문서 내용 Q&A(RAG), 검색 실패 로그 기반 사전 보강, 로컬 LLM 옵션, 대시보드 | 주간 사용량/성공률 리포트 |

> **Quick win (Phase 0에서 하루 만에 시연 가능)**: macOS Spotlight(`mdfind`)는 이미 많은 형식의 본문을 색인하고 있다.
> `mdfind -onlyin /Volumes/Share "미디어믹스"` 를 감싼 간단한 tool만 만들어도 개념 검증(PoC) 시연이 가능하다. 단, 권한·HWP·의미검색·랭킹이 안 되므로 운영용은 아님.

## 6. 품질 측정 & 개선 루프

- **평가셋**: 실제 직원에게 받은 질문 50~100개 + 정답 파일. 모델/가중치/사전을 바꿀 때마다 자동 실행.
- **지표**: Recall@5(정답이 상위 5개 안에 있나), MRR(정답이 몇 위인가), 0건 비율, 응답 시간(p95 < 5초 목표).
- **사용 로그 활용**: 사용자가 실제로 고른 파일 = 정답 신호. 고르지 않고 재검색한 쿼리 = 실패 사례 → 주간 리뷰로 동의어/규칙 보강.

## 7. 운영 규칙 (검색 품질을 공짜로 올리는 방법)

앞으로 저장되는 파일에 대해 가벼운 규칙만 정해도 정확도가 크게 오른다.

- 폴더: `/부서/연도/클라이언트/프로젝트/`
- 파일명: `YYYY(MM)_클라이언트_문서유형_제목_v버전` (예: `2022_알보칠_미디어믹스_상반기_v3.xlsx`)
- 최종본은 `_최종` 하나만, 이전 버전은 `_old` 폴더로

과거 파일은 인덱서가 메타데이터를 자동 추정하므로 **기존 파일을 다시 정리할 필요는 없다.**

## 9. 착수 전 결정 필요 사항

1. 대상 파일 규모 (파일 수 / 총 용량 / HWP·스캔 PDF 비중)
2. 저장 위치: 맥미니 내장/외장 SSD vs 기존 NAS
3. 사용 채널: Telegram 유지 vs Slack/카카오워크/웹 UI
4. 외부 LLM API로 파일명·스니펫이 나가는 것에 대한 회사 보안 정책 허용 여부
5. 권한 구분 수준: 전 직원 공통 vs 부서별 vs 폴더별
6. 게이트웨이 위치: Railway 유지 vs 맥미니로 이전 (권장: 이전)
